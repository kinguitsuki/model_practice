# RAG（Retrieval-Augmented Generation）の仕組み

## RAGとは

RAG は「検索拡張生成」と訳され、LLM が持たない最新情報・専門知識を
外部ドキュメントから動的に取得して回答を生成する技術です。

Lewis et al. (2020) "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"
で提案されました。

## RAG が解決する問題

| 問題              | RAG なし                  | RAG あり                        |
|-------------------|--------------------------|--------------------------------|
| 知識の鮮度        | 学習データの時点で停止    | リアルタイムで更新可能          |
| ハルシネーション  | 存在しない事実を生成しがち | 根拠テキストに基づいて回答      |
| コンテキスト長    | 全文書を入力できない      | 必要な部分だけ取得して渡す      |
| コスト            | 大量のコンテキストが必要  | 関連する少量のテキストで十分    |

## RAG の処理フロー

### インデックス構築フェーズ（オフライン）

```
ドキュメント読み込み
    ↓
テキスト分割（チャンキング）
    ↓
埋め込みベクトル生成（Embedding）
    ↓
ベクトルDB保存（FAISS/Chroma等）
```

### 検索・生成フェーズ（オンライン）

```
ユーザーのクエリ
    ↓
クエリの埋め込みベクトル生成
    ↓
類似度検索（コサイン類似度）
    ↓
上位k件のチャンクを取得
    ↓
LLMプロンプトに文脈として挿入
    ↓
LLMが文脈を参照して回答生成
```

## 埋め込みモデル（Embedding Model）

テキストを高次元ベクトルに変換するモデル。意味的に似たテキストは
ベクトル空間で近い位置に配置される。

### 代表的なモデル

| モデル名                             | 次元数 | 特徴                     |
|-------------------------------------|--------|--------------------------|
| intfloat/multilingual-e5-base       | 768    | 日本語対応、高品質       |
| intfloat/multilingual-e5-small      | 384    | 軽量、速い               |
| text-embedding-ada-002 (OpenAI)     | 1536   | 高品質（有料API）        |

### E5 モデルの使い方

E5 系モデルは prefix をつけると精度が上がる：
- 文書に: `passage: {テキスト}`
- クエリに: `query: {テキスト}`

## チャンキング（テキスト分割）

長い文書を LLM のコンテキストウィンドウに合わせて分割する処理。

### 再帰的テキスト分割

優先順位: `\n\n` → `\n` → `。` → `.` → ` ` → 文字

段落 → 文 → 単語の順に意味のある単位で分割。

### パラメータの目安

```
chunk_size   = 512文字  （長すぎると関係ない情報が混入）
chunk_overlap = 64文字  （チャンク境界の文脈切れを防ぐ）
```

## ベクトルデータベース

### FAISS（Facebook AI Similarity Search）
- ローカルで動作、無料
- IndexFlatIP: 内積での完全探索（小〜中規模向け）
- IndexIVFFlat: 近似検索（大規模向け）

### コサイン類似度 vs 内積
ベクトルを L2 正規化すると、内積 = コサイン類似度になる。
FAISS の IndexFlatIP + 正規化ベクトルでコサイン検索が実現できる。

## ハイブリッド検索

セマンティック検索（意味ベース）+ キーワード検索（BM25ベース）を
組み合わせることで精度を向上させる手法。

```
最終スコア = セマンティックスコア + キーワードマッチ数 × ボーナス係数
```

## 高度な RAG パターン

### Corrective RAG (CRAG)
取得した文脈が低品質（関係ない）場合に Web 検索にフォールバックする。

### Self-RAG
LLM 自身が「検索が必要か」を判断し、必要な場合のみ検索する。
「Retrieve」「IsRel」「IsSupported」などのトークンで動作を制御。

### HyDE（Hypothetical Document Embeddings）
クエリに対する仮想的な回答を LLM に生成させ、その回答ベクトルで検索する。
直接クエリより関連文書を見つけやすい。

### Re-ranker（クロスエンコーダー）
Bi-encoder（埋め込みモデル）で候補を絞り、
Cross-encoder でより精密なリランキングを行う 2 段階検索。
