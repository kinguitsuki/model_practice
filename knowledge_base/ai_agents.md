# AIエージェントとは

## 概要

AIエージェントとは、LLM（大規模言語モデル）を中心に、外部ツールや環境と相互作用しながら
自律的にタスクを遂行するシステムです。単なるQ&Aと異なり、エージェントは
「考える → 行動する → 観察する」を繰り返して複雑な問題を解決します。

## ReAct（Reasoning + Acting）フレームワーク

ReAct は Yao et al. (2022) が提案したエージェント設計パターンです。

### ReAct のループ構造

```
Thought:  現状の分析と次の行動の計画
Action:   ツールの選択
Action Input: ツールへの入力
Observation: ツールの実行結果
（Thought → Action → Observation を繰り返す）
Final Answer: 最終回答
```

### なぜ ReAct が有効か

- **思考の可視化**: Thought ステップにより推論プロセスが透明になる
- **ハルシネーション削減**: ツールで事実確認してから回答する
- **複雑タスク対応**: ステップを細分化することで長いタスクを処理できる

## ツール（Tool）

エージェントが呼び出せる外部機能。代表例：

| ツール名        | 説明                          |
|----------------|-------------------------------|
| RAG検索        | ナレッジベースからの情報検索   |
| 計算機         | 数式の評価・計算              |
| Web検索        | インターネットからの情報取得   |
| コード実行      | Pythonコードの実行            |
| データベース    | SQL によるデータ照会          |

## メモリの種類

### 1. 短期メモリ（会話バッファ）
現在の会話履歴を保持。コンテキストウィンドウに収まる範囲で参照。

### 2. 長期メモリ（ベクトルストア）
RAG により外部ドキュメントを検索。事実上無制限の情報を参照可能。

### 3. エピソードメモリ
過去の成功/失敗パターンを学習・記録する高度なメモリ。

## 最先端のエージェントパターン

### マルチエージェントシステム
複数のエージェントが協調・分業するシステム。
- **Orchestrator**: 全体の計画を立て、各エージェントに指示する
- **Worker**: 特定のタスクを専門的に実行する

### Reflection（自己反省）
エージェントが自分の出力を評価・改善するパターン。
1. 初回回答を生成
2. 自己批評する
3. 改善版を生成

### Plan-and-Execute
事前に実行計画を立ててから逐次実行するパターン。
長い多段階タスクに有効。

## エージェント設計のベストプラクティス

1. **ツールの説明を明確に**: エージェントがツール選択を誤らないよう、description を詳細に書く
2. **エラーハンドリング**: ツール失敗時でもループが継続できるよう設計する
3. **反復回数の制限**: max_iterations で無限ループを防ぐ
4. **メモリ管理**: トークン超過を避けるため、古い履歴は定期的に破棄する
5. **観測結果の圧縮**: 長い Observation はサマリーして LLM に渡す
