## 2. データが流れる順番（全体フロー）

### 起動時（インデックス構築フェーズ）

```
knowledge_base/ のドキュメント
        ↓  DocumentLoader.load()
    Document オブジェクト群
        ↓  RecursiveTextChunker.split()
    Chunk オブジェクト群（512文字ごとに分割）
        ↓  EmbeddingModel.embed_documents()
    numpy 配列（各チャンクを768次元ベクトルに変換）
        ↓  FAISSVectorStore.add()
    FAISS インデックス（高速検索用のデータ構造）
        ↓  .save()
    vector_store/ ディレクトリに永続化
```

### 質問時（推論フェーズ）

```
ユーザーの質問文字列
        ↓  interfaces/cli.py → agent.run()
    ConversationMemory に追記
        ↓  ReActAgent.run()  ← ここから ReAct ループ
    LLM に「思考してください」と送信
        ↓  Claude が Thought / Action / Action Input を生成
    テキストをパース → Action と Action Input を抽出
        ↓  tool.safe_run(action_input)
    ツール実行（例: rag_search → FAISSで検索 → 関連テキスト取得）
        ↓  Observation としてスクラッチパッドに追記
    LLM に再送信（思考続き）
        ↓  「Final Answer:」が来たらループ終了
    最終回答を ConversationMemory に追記して返す
```

RAGとは「聞かれたときに、まず関連ドキュメントを検索し、

### 3-2. テキスト分割（チャンキング）

**ファイル**: [rag/chunker.py](../rag/chunker.py)

長い文書をそのままベクトル化すると精度が落ちるため、
小さい単位（チャンク）に分割します。

#### なぜ分割が必要か

```
問題: 1万文字の文書を1つのベクトルにすると「平均的な意味」になってしまう
     → 特定の段落を精度よく検索できない

解決: 512文字ごとに分割して個別にベクトル化
     → 「この段落はAについて、この段落はBについて」と精度よく検索できる
```

#### 再帰的テキスト分割のアルゴリズム

```python
_SEPARATORS = ["\n\n", "\n", "。", ".", "、", ",", " ", ""]
#              段落   改行   句点  ピリオド 読点  カンマ 空白  強制
```

優先度順に「良い分割点」を探します：

```
Step 1: "\n\n" (段落区切り) で分割を試みる
Step 2: 512文字超えたら → "\n" で試みる
Step 3: それでも超えたら → "。" で試みる
...
Step N: どうしても無理なら → 文字数で強制分割
```

#### オーバーラップ（重複部分）の意味

```
チャンク1: [----本文A----][←重複64文字→]
チャンク2:               [←重複64文字→][----本文B----]
```

チャンク境界で話題が切れても、隣接するチャンクが文脈を引き継ぎます。
例：「Xは非常に重要で、」で切れても次のチャンクに「非常に重要で、なぜなら」が入る。

### 3-3. 埋め込みベクトル

**ファイル**: [rag/embedder.py](../rag/embedder.py)

テキストを「意味の座標」に変換します。

```
"RAGとは検索技術です"  →  [0.12, -0.34, 0.89, ...]  (768個の数値)
"検索拡張生成の仕組み" →  [0.11, -0.31, 0.92, ...]  (768個の数値)

↑ 意味が近いので数値も近い！
```

#### E5 モデルのプレフィックスの秘密

```python
# 文書チャンク（長い説明文）
"passage: RAGとはRetrieval-Augmented Generationの略で..."

# 検索クエリ（短い質問）
"query: RAGとは何ですか？"
```

モデルは学習時に「query: と passage: の組み合わせの類似度」を最大化するよう訓練されています。
プレフィックスを付けることで、質問文と回答文が異なる文体でも高精度にマッチします。

#### L2正規化（なぜするか）

```python
vectors = self._model.encode(texts, normalize_embeddings=True)
```

ベクトルの「長さ」を全て1に揃えます。これにより：

```
内積 A·B = |A||B|cos(θ) = 1 × 1 × cos(θ) = cos(θ)
```

内積の計算がそのままコサイン類似度になります。FAISSの `IndexFlatIP`（内積検索）でコサイン検索が実現できます。

### 3-5. ハイブリッド検索

**ファイル**: [rag/retriever.py](../rag/retriever.py)

セマンティック検索だけでは「意味は近いけどキーワードが外れている」問題が起きます。

```python
def retrieve(self, query: str, top_k: int) -> List[Tuple[Chunk, float]]:
    # Step 1: FAISSで多めに取る（top_k × 2 件）
    candidates = self._store.search(query_vec, top_k=top_k * 2)

    # Step 2: キーワードボーナスを加算してリランク
    reranked = self._keyword_rerank(query, candidates)

    # Step 3: 上位 top_k 件に絞る
    return reranked[:top_k]
```

キーワードボーナスの計算：

```python
query_tokens = set("RAG 仕組み".lower().split())  # {"rag", "仕組み"}
doc_tokens   = set(chunk.content.lower().split())  # {"rag", "とは", "仕組み", ...}

overlap = len(query_tokens & doc_tokens)  # 集合の積 → 2
bonus = overlap * 0.02                   # +0.04 のボーナス
```

## 4. ReActエージェント — 考えて行動する仕組み

### 4-1. ReActとは何か

**ファイル**: [agent/core/agent.py](../agent/core/agent.py)

ReAct = **Re**asoning + **Act**ing。2022年に提案された論文のパターンです。

普通のLLMは「質問 → 回答」の1往復。
ReActは「質問 → 考える → 行動する → 観察する → 考える → ...→ 最終回答」の多往復。

```
質問: 「広告費50万円の場合の売上予測と、その値を2倍にすると？」

【ReActなし】
LLM: 「おそらく〇〇万円くらいかと思います...」
     ← ハルシネーション（根拠のない回答）

【ReActあり】
Thought: MLモデルで予測し、計算ツールで2倍にすれば答えられる
Action: ml_inference
Action Input: 50
Observation: 広告費 50万円 → 予測売上: 130.0万円

Thought: 予測値130万円が得られた。次に2倍を計算する
Action: calculator
Action Input: 130 * 2
Observation: 260

Thought: 全情報が揃った
Final Answer: 広告費50万円の予測売上は130万円で、その2倍は260万円です
```

---

### 4-2. プロンプトの設計

`_SYSTEM_PROMPT` が ReAct の「ルールブック」です。

```python
_SYSTEM_PROMPT = """\

## 出力フォーマット（必ず守ること）

Action Input: [入力]

```

`{tools}` には実際には以下が展開されます：

```

- calculator: 数学的な計算を行います。例: '2 + 3 * 4'...
- ml_inference: 広告費（万円）から売上を予測します。...
```

LLMはこのシステムプロンプトを読んで、どのツールをいつ使うかを自分で判断します。

### 4-3. ループの詳細コード解説

[agent/core/agent.py:91-145](../agent/core/agent.py) の `run()` メソッドを追います。

```python
def run(self, user_input: str) -> str:
    # ① 会話履歴に追記
    self._memory.add("user", user_input)

    # ② スクラッチパッド = 「このターンの思考メモ帳」
    #    最初は質問文そのもの
    scratchpad = user_input

    # ③ 過去の会話履歴（最新のuser発言は除く）
    history = self._memory.get_messages()[:-1]

    for iteration in range(1, self._max_iter + 1):

        # ④ LLM に送信
        response = self._llm.chat(
            messages=history + [{"role": "user", "content": scratchpad}],
            system=system,
        )
        llm_text = response.content.strip()
```

**ポイント①**: `scratchpad` の内容の変化

```
【1回目】
scratchpad = "広告費50万円の売上予測は？"

【2回目（ツール使用後）】
scratchpad = """広告費50万円の売上予測は？
Thought: MLモデルで予測します
Action: ml_inference
Action Input: 50
Observation: 広告費 50万円 → 予測売上: 130.0万円
"""
```

LLMは毎回この「思考の経緯」全体を受け取り、続きを生成します。

**ポイント②**: `history = []` の意味

```python
# 2回目以降はhistoryを空にする
history = []
```

1回目: `[過去の会話] + [今回の質問]`  
2回目: `[スクラッチパッド全体]`（過去の会話はスクラッチパッドに含まれているため不要）

これによりトークン数を大幅に節約できます。

**ポイント③**: Final Answerの検出

```python
if "Final Answer:" in llm_text:
    answer = llm_text.split("Final Answer:")[-1].strip()
    # "Final Answer:" より後ろのテキストだけを取り出す
    return answer
```

### 4-4. テキストのパース処理

[agent/core/agent.py:156-166](../agent/core/agent.py) の `_parse_action()` です。

LLMが出力したテキストから「何のツールを、どの入力で使うか」を抽出します。

```python
def _parse_action(self, text: str) -> tuple[Optional[str], str]:
    # "Action: ツール名" を抽出（改行または行末まで）
    action_match = re.search(r"Action:\s*(.+?)(?:\n|$)", text)

    # "Action Input: 入力内容" を抽出（複数行対応）
    input_match = re.search(
        r"Action Input:\s*([\s\S]+?)(?:\n(?:Thought|Action|Final Answer|Observation)|$)",
        text
    )
```

正規表現の解読：

| パターン | 意味 |
|----------|------|
| `Action:\s*` | 「Action:」の後の空白0個以上 |
| `(.+?)` | 何らかの文字（最小マッチ） |
| `(?:\n\|$)` | 改行または行末 |
| `[\s\S]+?` | 改行含む任意の文字（最小マッチ） |
| `(?:\n(?:Thought\|Action\|...)` | 次のReActキーワードが来るまで |

実例：

```
入力テキスト:
"Thought: 計算します\nAction: calculator\nAction Input: 2 + 3\nObservation: ..."

抽出結果:
action       = "calculator"
action_input = "2 + 3"
```

## 5. ツール群 — エージェントの「手足」

### 基底クラス（BaseTool）

**ファイル**: [agent/tools/base.py](../agent/tools/base.py)

```python
class BaseTool(ABC):
    name: str          # エージェントがプロンプトで読む識別子
    description: str   # エージェントが「いつ使うか」を判断する説明文

    @abstractmethod
    def run(self, tool_input: str) -> ToolResult:
        ...

    def safe_run(self, tool_input: str) -> ToolResult:
        try:
            return self.run(tool_input)
        except Exception as exc:
            return ToolResult(success=False, output="", error=str(exc))
            # ← 例外をキャッチしてエラー情報をObservationとして返す
            # ← これがないと例外でループが止まってしまう
```

`safe_run()` のおかげで、ツールが失敗しても：

```
Observation: ツールエラー: 数値を入力してください (例: '50')
```

というObservationがLLMに届き、LLMが「入力を修正してリトライしよう」と判断できます。

### 計算機ツール（ASTサンドボックス）

**ファイル**: [agent/tools/calculator.py](../agent/tools/calculator.py)

`eval("入力文字列")` は危険（任意コードが実行される）なので使いません。
代わりにPythonのAST（抽象構文木）を手動でウォークします。

```python
# 普通の eval は危険
eval("__import__('os').system('rm -rf /')")  # 実行されてしまう！

# ASTパースなら安全
tree = ast.parse("sqrt(16)", mode="eval")
# → 許可リスト内の演算子・関数しか実行しない
```

許可リスト（ホワイトリスト）方式：

```python
_SAFE_OPS = {
    ast.Add: operator.add,    # +
    ast.Sub: operator.sub,    # -
    ast.Mult: operator.mul,   # *
    ast.Div: operator.truediv, # /
    ast.Pow: operator.pow,    # **
    ...
}
_SAFE_MATH = {  # math モジュールの関数のみ
    "sqrt": math.sqrt,
    "log": math.log,
    ...
}
```

上記以外の処理（`import`、`open`、クラス定義など）は全て `ValueError` で弾きます。

## 6. 会話メモリ — 文脈を保持する仕組み

**ファイル**: [agent/core/memory.py](../agent/core/memory.py)

```python
class ConversationMemory:
    def get_messages(self) -> List[dict]:
        # 直近 max_window × 2 件だけ返す
        recent = self._history[-(self._max_window * 2):]
        return [{"role": m.role, "content": m.content} for m in recent]
```

なぜ `max_window * 2` か：
- ユーザー発言 1つ + アシスタント回答 1つ = 1ターン = 2メッセージ
- `max_window = 10` なら、直近10ターン分 = 20メッセージを保持

スライディングウィンドウのイメージ：

```
turnA user     ← 古い順
turnA assistant
turnB user
turnB assistant
   ...（ここより古いものは切り捨て）
turnI user     ← ウィンドウ内（直近10ターン）
turnI assistant
turnJ user     ← 最新
turnJ assistant
```

## 7. LLM層 — Claudeとの通信

**ファイル**: [llm/claude.py](../llm/claude.py)

```python
def chat(self, messages: list[dict], system: Optional[str] = None) -> LLMResponse:
    kwargs = {
        "model": self._model,
        "max_tokens": settings.max_tokens,
        "messages": messages,
    }
    if system:
        # ← プロンプトキャッシュ（重要！）
        kwargs["system"] = [{
            "type": "text",
            "text": system,
            "cache_control": {"type": "ephemeral"}
        }]

    response = self._client.messages.create(**kwargs)
```

#### プロンプトキャッシュとは

ReActのsystemプロンプトは1回の会話の中で何度も同じ内容をAPIに送ります。
`cache_control: ephemeral` を付けると、Anthropicのサーバーが
**同じsystemプロンプトをキャッシュ**してくれます。

```
通常:     [system 1500トークン] + [user 200トークン] = 1700トークン課金 × 10回
キャッシュ:[system 1500トークン（初回のみ）] + [user 200トークン] × 10回
          ≈ 90%のコスト削減
```

#### BaseLLMの抽象化の理由

```python
class BaseLLM(ABC):
    @abstractmethod
    def generate(self, prompt: str, ...) -> LLMResponse: ...

    @abstractmethod
    def chat(self, messages: list[dict], ...) -> LLMResponse: ...
```

`ClaudeLLM` の代わりに `OpenAILLM` を作れば、エージェント・RAGのコードは
**一行も変えずに** GPT-4 に切り替えられます。これが「抽象化」の価値です。

```python
class Settings(BaseSettings):
    anthropic_api_key: str = ""
    claude_model: str = "claude-sonnet-4-6"
    chunk_size: int = 512

    class Config:
        env_file = ".env"
```

pydantic-settingsは以下の優先順位で設定を読みます：

```
1. 環境変数        CHUNK_SIZE=1024 python main.py  ← 最優先
2. .env ファイル   CHUNK_SIZE=1024
3. デフォルト値    chunk_size: int = 512           ← 最低優先
```

型チェックも自動：

```
# .env に間違った設定をした場合
CHUNK_SIZE=abc  → 起動時に ValidationError で即座に検出
```

## 9. 各コンポーネントの依存関係図

矢印は「依存している方向」（A → B = AがBを使う）

```
main.py
  └──→ interfaces/cli.py
         ├──→ agent/core/agent.py   (ReActAgent)
         │      ├──→ llm/claude.py  (ClaudeLLM)
         │      ├──→ agent/core/memory.py
         │      └──→ agent/tools/
         │              ├── rag_search.py ──→ rag/pipeline.py
         │              │                      ├──→ rag/document_loader.py
         │              │                      ├──→ rag/chunker.py
         │              │                      ├──→ rag/embedder.py
         │              │                      ├──→ rag/vector_store.py
         │              │                      └──→ rag/retriever.py
         │              ├── calculator.py  (外部依存なし)
         │              └── ml_inference.py ──→ src/model.py (既存コード)
         └──→ rag/pipeline.py (インデックス構築時)

全モジュール ──→ config/settings.py
```

重要な設計原則：**内側のモジュールは外側を知らない**

- `rag/` は `agent/` を知らない → RAG単体でテスト・利用できる
- `llm/` は `agent/` を知らない → LLM単体でテスト・利用できる
- `config/` は全モジュールが使うが、それ自体は他に依存しない

## 10. 実際の実行トレース（質問から回答まで）

**質問**: 「RAGの仕組みを教えて、それと広告費30万円の売上予測も教えて」

```
① main.py → interfaces/cli.py → ReActAgent.run("RAGの仕組みを...")
   ↓
② memory.add("user", "RAGの仕組みを...")
   ↓
③ scratchpad = "RAGの仕組みを..."
   history = []  (初回なので空)
   ↓
④ [ReActループ 1回目]
   llm.chat(messages=[{"role":"user", "content":"RAGの仕組みを..."}], system=...) を呼ぶ
   ↓
   Claude の応答:
   """
   Thought: RAGの仕組みについてナレッジベースを検索し、
            売上予測はMLツールを使います。まずRAGを検索します。
   Action: rag_search
   Action Input: RAG 仕組み 概要
   """
   ↓
⑤ _parse_action() で抽出:
   action = "rag_search"
   action_input = "RAG 仕組み 概要"
   ↓
⑥ tools["rag_search"].safe_run("RAG 仕組み 概要")
   → EmbeddingModel.embed_query("query: RAG 仕組み 概要")  # ベクトル変換
   → FAISSVectorStore.search(query_vec, top_k=10)           # 類似ベクトル検索
   → HybridRetriever._keyword_rerank(...)                   # キーワードでリランク
   → 上位5チャンクを整形したテキストを返す
   ↓
⑦ observation = "【参考資料1】出典: rag_explained.md\nRAGとはRetrieval..."
   scratchpad = "RAGの仕組みを...\nThought: ...\nAction: rag_search\n...Observation: 【参考資料1】..."
   history = []  (2回目以降はscratchpadに全文脈が入っているため不要)
   ↓
⑧ [ReActループ 2回目]
   llm.chat(messages=[{"role":"user", "content": scratchpad全体}], system=...) を呼ぶ
   ↓
   Claude の応答:
   """
   Thought: RAGの情報が得られました。次に売上予測を行います。
   Action: ml_inference
   Action Input: 30
   """
   ↓
⑨ tools["ml_inference"].safe_run("30")
   → _get_model() でLinearRegressionを初回学習（キャッシュ済みならスキップ）
   → model.predict([[30]]) で予測
   → "広告費 30.0万円 → 予測売上: 79.8万円" を返す
   ↓
⑩ scratchpad にObservationを追記
   ↓
⑪ [ReActループ 3回目]
   llm.chat(...) を呼ぶ
   ↓
   Claude の応答:
   """
   Thought: RAGの情報と売上予測が揃いました。
   Final Answer: RAGとはRetrieval-Augmented Generationの略で...
   また、広告費30万円の場合の売上予測は約79.8万円です。
   """
   ↓
⑫ "Final Answer:" を検出 → ループ終了
   answer = "RAGとはRetrieval-Augmented Generationの略で..."
   memory.add("assistant", answer)
   return answer
   ↓
⑬ cli.py が受け取って print() で表示
```
