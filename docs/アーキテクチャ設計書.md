# アーキテクチャ設計書

## システム概要

RAG（Retrieval-Augmented Generation）と ReAct エージェントを組み合わせた
AI アシスタントシステムです。ナレッジベースから関連情報を動的に取得しながら、
複数ツールを駆使して複雑な質問に回答します。

## 依存関係の方向

```
interfaces  →  agent  →  llm
                       →  rag
                       →  tools → src (既存ML)
                       →  config
```

外側のレイヤーは内側に依存するが、**内側は外側を知らない**。
これにより、CLI を API に置き換えても agent/rag/llm は変更不要。

## 設計上の決定事項

### 1. LangChain を使わずスクラッチ実装した理由

LangChain は抽象化が厚く、内部で何が起きているかを学習者が追いにくい。
RAG の各ステップ（chunk → embed → store → retrieve）を明示的に実装することで、
各技術の理解を深められる。

### 2. FAISS をローカルで使う理由

- **無料**: Pinecone/Weaviate などのクラウドVDBは有料
- **高速**: インメモリ検索で低レイテンシ
- **シンプル**: API キー不要、ファイル保存のみ

### 3. sentence-transformers を使う理由

- **ローカル動作**: OpenAI Embedding API と異なり API コストゼロ
- **日本語対応**: multilingual-e5-base は日本語精度が高い
- **オフライン利用可能**: 初回ダウンロード後はネット不要

### 4. pydantic-settings による設定管理

- `.env` ファイルから自動読み込み
- 型安全（`int` として定義した項目に文字列が来たらエラー）
- テスト時に環境変数を上書きするだけで設定変更できる

## 拡張ポイント

| やりたいこと                   | 変更するファイル                         |
|-------------------------------|----------------------------------------|
| GPT-4 に切り替え               | `llm/openai.py` を新規作成し BaseLLM を継承 |
| Pinecone に切り替え            | `rag/vector_store.py` の FAISSVectorStore を差し替え |
| Web 検索ツールを追加           | `agent/tools/web_search.py` を新規作成 |
| ドキュメントを追加             | `knowledge_base/` にファイルを置いて rebuild |
| Self-RAG パターンを実装        | `rag/retriever.py` に検索品質判定ロジックを追加 |
